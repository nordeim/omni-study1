# StudyFlow (Omni-Study)

## Core Identity & Purpose

StudyFlow is a self-hosted study-companion web app — a production-grade clone (functional superset, visual parity) of `omni-study1.base44.app`. Twenty views (dashboard, tasks, calendar, timetable, assignments, exams, notes, flashcards, practice tests, study groups, grade tracker, analytics, files, calculator suite, math solver, AI assistant, focus timer, settings) over a Prisma/SQLite backend with email/password auth and server-side AI features. Maintained by the repo owner (`nordeim`); primary consumers are the owner and any future coding agents working in this repo.

Key decisions that shape everything else: **Next.js 16 App Router as a one-page SPA** (twenty rewritten paths, client-side view switching — matching the reference app's routing behavior); **SQLite at the repo root** (zero-config, one file, a documented three-anchor resolution contract); **Tailwind v4 with v3-pinned tokens** (visual parity requires pinning palette + shadow geometry against v4's engine changes).

## Foundational Principles

### Meticulous Approach (Six-Phase Workflow)

1. **ANALYZE** — Read the affected files completely before changing them; reproduce any reported failure before theorizing about it. Prefer executable truth (configs, lockfiles, computed styles) over prose.
2. **PLAN** — Lay out the change as sequential, individually verifiable steps. For UI-parity work, list the measured tokens you are matching.
3. **VALIDATE** — Confirm the plan against the acceptance criteria (and the reference app when parity is involved) before writing code.
4. **IMPLEMENT** — Smallest safe diff; respect the conventions below; update the touched tests in the same change.
5. **VERIFY** — Run the full gate: `bun run lint && bun run typecheck && bun run test && bun run build && bun run test:e2e`. Browser-verify interactive changes (agent-browser or Playwright) — a green build is not evidence a page works.
6. **DELIVER** — Conventional-commit the atomic change; update docs when behavior or setup steps change; hand off honestly (what was verified, what wasn't, what remains).

### Project-Specific Principles

- **Parity is measured, not guessed.** Computed styles from the live reference are the ground truth; screenshots are secondary. Every parity fix lands with a pinning test where feasible.
- **One database file, three anchors.** The `DATABASE_URL` contract (see Project_Architecture_Document.md ADR-002) is the most fragile invariant in the repo — treat changes to it as high-risk.
- **The local gate is the only gate.** No CI exists; nothing ships that hasn't passed lint/typecheck/test/build/e2e locally.
- **Audit tools self-verify (S27/ADR-025); verdicts assert the designed channel (S28/ADR-026).** A probe sets state only through the real application path (the settings API — never a forced class or a private side-channel) and asserts its own precondition, failing loudly (non-zero exit, no findings) when it cannot verify the state it is about to measure; the applied state rides the structured output. Silent tooling rot under app change is how `dark-sweep.mjs` swept in light mode for 15 sessions (AP-72). The verdict side of the same doctrine (AP-73): a probe's assertion must track the DESIGN — when a change replaces a failure channel (S15: login errors toasts → inline role=alert), the probe asserting the retired channel emits phantom findings disproved by their own measured evidence; the tell is a finding whose measured JSON contains the very feedback it claims is absent. Assert the designed channel scoped to its container, keep the genuine-failure criterion loud, and re-run every standing audit after any change that touches what it measures — reading the findings array, not the aggregate verdict.

## Implementation Standards

### General Coding Practices

- Early returns over nesting; composition over inheritance; self-documenting names.
- TypeScript strict; `unknown` instead of `any`; no unused imports (lint gates it).
- Pure logic lives in `src/lib/*` seams with unit tests; views orchestrate, they don't compute.

### Language & Framework Guidelines

**Next.js 16 / React 19**
- App Router; `src/app/page.tsx` is the ONLY app route (plus `/login`). The 20 view paths are rewrites — never create per-view route folders.
- Route handlers: thin shells over the CRUD factory (`src/lib/server/`); always `userId`-scope Prisma queries; always validate through `src/lib/validation.ts` schemas.
- `"use client"` at the top of every component file; server-only imports (`z-ai-web-dev-sdk`, `node:crypto`) never appear in client modules.

**Tailwind CSS v4 (CSS-first)**
- No `tailwind.config.js`. All tokens live in `src/app/globals.css` under `@theme inline`.
- **Dark-mode token contract (session-10):** the shadcn base tokens route through raw triplet vars (`:root`/`.dark` `--card`, `--popover` …) consumed as `hsl(var(--x))` inside `@theme inline` — literal values there are INLINED into utilities at build time and `.dark` overrides never reach them (white dialogs + invisible outline buttons in dark mode). Shadows route through `--sf-shadow-sm`; re-theming gradients/tints live in globals.css classes with `.dark` overrides (`.sf-overdue-banner`, `.sf-amber-card`, `.sf-today-*`, `.sf-clock-chip`, `.sf-selected-tint`), never inline styles. The reference's own Dark option is a measured platform no-op — the clone's full dark mode is the documented superset. **Theme-application lifecycle (session-11):** a pre-paint boot script (`THEME_BOOT_SCRIPT`, `<head>` in the root layout) applies the cached mode from `localStorage["sf-theme"]` (written by `applyToDocument` on every apply — format unit-pinned) with a `matchMedia` fallback for fresh visitors; System mode tracks OS changes at runtime via `installSystemThemeTracking()`; sign-out clears the cache; a plain `meta[name=theme-color]` tracks the effective mode. Accent-driven text in dark follows the 300-level convention (`dark:text-sf-primary-strong-dark` / the `.sf-nav-active` classes) — light values stay byte-identical.
- **Accessibility contract (session-12):** state must survive without fills — forced-colors and print both strip them. Forced-colors: system-color (`Highlight`) inset outlines on the state surfaces (calendar selected/today, mode switch, active tab, timetable today header), `font-weight: 700` on the active nav (`nav a[aria-current=page]` AND its `span` — inherited weights lose to the inner `font-medium` utility), `forced-color-adjust: none` on `.sf-slider-fill` only (essential graphic). Print: the boot script's `beforeprint`/`afterprint` handlers force light for the print duration; `sf-print-exact` (`print-color-adjust: exact`, inherited) on every white-text-on-color container (`.sf-gradient` carries it directly — the Button default variant, the events panel, the timetable canvas, the calendar month card, the checked checkboxes, the raw dashboard/myday CTAs); `.sf-timetable-canvas` resets `min-width: 0` in print. The skip link (`.sf-skip-link`) is off-screen, never `display: none`. Reduced-motion: the global collapse block. All superset — the reference has none of these.
- **Resilience contract (session-13):** failure states are first-class. Every AI call site passes `{ timeoutMs: 120_000 }` to `apiSend` (`AbortSignal.timeout`) — a hung backend must never disable a composer forever; `isTimeoutError(err)` maps the deadline to a "took too long" toast. The AI chat's optimistic message is rolled back on failure (`removeChatMessage(localId)` + `setInput(content)` — the bounced-back text IS the retry affordance; never orphan it). Uploads reject empty/whitespace filenames (the Bun standalone surfaces them as `undefined` — a 500, worse than dev's stored `""`); downloads use `buildContentDisposition()` — ASCII-safe fallback + RFC 5987 `filename*=UTF-8''…`. Unbounded list endpoints are a VERIFIED non-gap at 300+ rows (zero long tasks) — don't add pagination without re-running `scripts/data-volume-audit.mjs`.
- **Connectivity contract (session-14):** the offline state is ambient — a `ConnectivityBanner` (`useSyncExternalStore` over `navigator.onLine`) renders null online (byte-identical DOM) and a `role="status"` amber pill offline; transport failures map to the human offline message at the `doFetch` seam in `src/lib/api.ts` (timeout classification first, untouched). No service worker/offline queue by decision.
- **Security-hardening contract (session-14; boot guard session-22):** the four AI routes enforce `checkRateLimit(`ai:${user.id}`, 20)` (429 + Retry-After); file downloads carry `nosniff` + `private, no-store`; no upload MIME allowlist by decision (parity — hardening rides the headers); whitespace-only display names 400. **AUTH_SECRET boot guard (ADR-020):** `src/instrumentation.ts` `register()` consults the pure seam `src/lib/env-check.ts` (`authSecretBootStatus`) once per server boot — production without a real secret (missing/empty/the pasted `DEV_FALLBACK_SECRET`, whose single source is the seam) exits via `console.error` + `process.exit(1)` with the `openssl rand -hex 32` remedy (a plain `throw` is caught by Next and degrades to a 500-server — the exit is the validated mechanism); short (< 32 chars) secrets warn; dev/test keep the documented fallback with one warn line.
- **Auth-flow contract (session-15, ADR-013):** the reference's full account journey — signup (Email/Password/Confirm), 6-digit email verification (15-min one-shot `VerificationToken`; no auto-login on register; unverified login gated 403 with the reference copy, after password verification), 3-state forgot-password (always-200 request; 30-min one-shot `PasswordResetToken`; reset deep-links via `/login?token=` read by the SERVER page component and seeded into the client state machine as a prop). No SMTP: the code/reset URL surface to the actor (response JSON + muted on-screen notes — the documented self-hosted trade-off). Auth errors render inline (`role="alert"` red/green alert blocks, measured chrome) — never as toasts. The seeded demo user is `emailVerified: true` (idempotent seed upgrade for pre-S15 dbs).
- **Load-stability contract (session-16, ADR-014):** the shell pre-warms the active view's initial collections in parallel with auth (`src/lib/view-collections.ts`, unit-pinned) and flips from the Splash only when both settle — the first paint renders with final geometry (dashboard CLS 0.00, was 0.117–0.125). A failed pre-warm never blocks the shell. Auth sub-screens render the reference's responsive mobile geometry (text-xl sm:text-2xl h2s, h-11 sm:h-12 Sign in, the mb-5 sm:mb-8 verify rhythm) — desktop values byte-identical.
- **RUM observability contract (session-18, ADR-016):** the authed shell mounts an invisible beacon (`<RumBeacon />` — renders null, zero DOM) reporting web-vitals to `/api/rum` (batched keepalive POSTs, upsert on sessionId+metric, 1000/15-min per-user budget, all failures swallowed); `GET /api/rum` answers p75 + recent samples. The login route stays un-instrumented (abuse-surface decision). Docker: the multi-stage `Dockerfile` + compose (SQLite on the /data volume, AUTH_SECRET required) — layout validated outside Docker, first real `docker compose --profile init up` on the owner's host is the remaining step.
- **RUM diagnostics panel contract (session-19, ADR-017; v3 session-20, ADR-018):** the auth-gated `/rum` route (a SERVER component — getCurrentUser + redirect("/login") gates anonymous visitors pre-render) renders `<RumPanel />` — the five CWV at p75 with rating badges re-derived from the PUBLIC bounds (the pure seam `src/lib/rum-diagnostics.ts`: `classifyP75`/`formatMetricValue`/`buildPanelRows`, unit-pinned), a samples line, the 10 most recent events, and a Refresh action. The panel themes through the production path (boot script + `loadFromUser`). It is linked from NOWHERE — the shell's 20-link parity stays byte-intact (an e2e guard pins the shell /rum-link-free); the owner navigates directly. The v3 additions (S20): GET /api/rum answers the per-metric `trends` series (≤ 20 most recent values, oldest → newest) rendered as accent-themed sparkline SVGs on the sampled cards (the pure `buildSparklinePoints` seam — the empty/single-value/flat-series edge cases are unit-pinned; `vectorEffect="non-scaling-stroke"` keeps the stroke uniform under `preserveAspectRatio="none"`), and GET /api/rum/export downloads the most recent 2000 events as a spreadsheet-ready text/csv (the pure `toRumCsv` seam — RFC-4180 escaping, RAW analysis-grade values; the S13 `buildContentDisposition` + nosniff + private/no-store header contract; 401 JSON for anonymous callers — the API-route convention) via a real Export CSV anchor on the panel.
- **Data portability contract (session-21, ADR-019):** the auth-gated `/export` route (a SERVER component — getCurrentUser + redirect("/login"), the /rum gate pattern) computes the per-collection count snapshot server-side and renders `<ExportPanel />` (themes through the production path) with the 20-collection count grid + a real **Download JSON** anchor to `GET /api/export/data` — the 20 content collections read in parallel (userId-scoped, chronological), assembled by the PURE seam (`src/lib/data-export.ts`: `EXPORT_COLLECTIONS` the stable manifest, `serializeExportRow` [userId dropped, Date → ISO], `buildDataExport` the versioned envelope [format `studyflow-data-export`, version 1, hashless `user`]), answered `application/json` with the S13/S14 download-header contract. EXCLUDED by decision: the password hash (the route's explicit select never reads it AND the seam strips it — the secret guard is unit-pinned), VerificationToken/PasswordResetToken (secrets), RumEvent (telemetry — the RUM CSV covers it); NO restore/import (the schema + SQLite file are the restore story). Linked from NOWHERE — the shell's 20-link parity stays byte-intact (an e2e guard pins the shell /export-link-free); the owner navigates directly (README + DEPLOYMENT.md §8.2). The session-23 RESTORE half (`POST /api/import/data`, ADR-021): the same envelope POSTs back — upsert-by-id in ONE all-or-nothing transaction (existing rows update to the file's values, new ids create with the importer's userId [portable across accounts], never deletes, content only), the pure seam `src/lib/data-import.ts` pre-validates (dangling optional FKs nulled, the required `cards.deckId` rejected, folders sorted parents-first with cycle rejection — Prisma's P2003 never surfaces opaquely), a 10 MiB cap + a 10/15-min per-user rate limit, and the `/export` page's **Restore from a backup** card drives it (the pinned S21 surfaces stay byte-identical).
- **Change-password contract (session-24, ADR-022):** the account-security rotation — `POST /api/auth/change-password` lets a signed-in user rotate their own password WITHOUT the forgot-password dance: `requireUser` → `checkRateLimit(`changePw:${user.id}`, 10)` → the Zod `changePasswordSchema` (the register family's min-8/max-200 policy on BOTH fields + the must-differ `.refine` whose message IS the actionable copy, unit-pinned) → the current password VERIFIED against the stored scrypt hash FIRST (wrong current → 400 pre-write; the caller is the authenticated owner, no enumeration surface) → the new hash written. The session SURVIVES the rotation by design (stateless HMAC over AUTH_SECRET — revoking other sessions is the rejected per-request-epoch alternative). The UI is the Settings Profile tab's **Change password** card (a purely additive sf-card BELOW the pinned S17 surfaces — the S23 Restore-card pattern): three autoComplete-typed password fields, client-side pre-checks (all-filled / min-8 / confirm-match / must-differ), errors INLINE as `role="alert"` (the S15 auth convention), success as `role="status"` + fields cleared. The reference has NO password surface (verified) — a pure superset; the e2e mutation journey runs on a FRESH registered user (the S17 convention — the demo hash is never mutated).
- **Account-deletion contract (session-25, ADR-023):** the ownership exit — `POST /api/auth/delete-account` lets a signed-in user permanently erase their own account: `requireUser` → `checkRateLimit(`delAcc:${user.id}`, 10)` → the Zod `deleteAccountSchema` (the register family's min-8/max-200 policy on the password + the typed-confirmation `.refine` demanding the CASE-EXACT word `DELETE`, whose message IS the actionable copy, unit-pinned) → the password VERIFIED against the stored scrypt hash FIRST (wrong password → 400 pre-write) → the ONE cascade write `db.user.delete` (all 22 user relations carry `onDelete: Cascade` — verified by grep + pinned empirically in the capture at the DB level) → the session cookie CLEARED (maxAge 0 — the logout mechanism; a surviving cookie is doubly dead: the user id no longer resolves). The UI is the Settings Profile tab's **Danger zone** card (a purely additive sf-card BELOW the S24 card): the two-step reveal (the form is HIDDEN until "Delete account…" — an accidental Enter must never fire), the warning copy with the export-first pointer, Password + Confirmation ("Type DELETE") fields, a `variant="destructive"` final button + Cancel, errors INLINE as `role="alert"`, NO success note — the theme cache is cleared and `window.location.replace("/login")`; the redirect IS the feedback. The reference has NO deletion surface (verified) — a pure superset; the e2e terminal journey runs on a FRESH registered user whose register/verify POSTs ride a DISTINCT client IP (x-forwarded-for — the suite's register/verify budgets were already at their 10/IP caps).
- **Email-change contract (session-26, ADR-024):** the account-identity rotation — `POST /api/auth/change-email` lets a signed-in user change the address they log in with: `requireUser` → `checkRateLimit(`changeEmail:${user.id}`, 10)` → the Zod `changeEmailSchema` (the register family's min-8/max-200 policy on the password + the email shape everywhere + the confirm-match `.refine` whose message IS the actionable copy — a mistyped address is UNRECOVERABLE through the UI, unit-pinned) → the password VERIFIED against the stored scrypt hash FIRST (wrong password → 400 pre-write) → the ROUTE-side guards (the current email is server state, not a body field): must-differ (the account's own address → 400) + uniqueness (ANY existing owner, verified or not → 409) → the ONE write `db.user.update` (lowercased; `emailVerified` STAYS TRUE — with no SMTP a re-verification OTP would surface to the same actor who just proved the password, proving nothing, and creating a lockout footgun) → the session cookie UNTOUCHED (stateless HMAC survives — the S24 contract); the response carries the new email so the client updates the theme store's user slice. The UI is the Settings Profile tab's **Email address** card (a purely additive sf-card BELOW the main Profile card and ABOVE the S24 card: identity → security → destructive exit; always visible — no two-step reveal, email change is NOT destructive): New email + Confirm new email + Password fields, errors INLINE as `role="alert"`, a `role="status"` success note + the fields cleared + the LIVE identity-block/sidebar update through the store's `setEmail` action (`src/lib/store.ts` — the setAvatar pattern). The reference has NO email-change surface (verified) — a pure superset; the e2e rotation journey runs on a FRESH registered user whose register/verify POSTs ride DISTINCT client IPs (192.0.2.26/.27 — the loopback register budget is at its 10/IP cap, the AP-71-corrected count).
- **Fresh-user journey contract (session-17, ADR-015):** registrations create zero subjects and the zero-data views mirror the reference's measured fresh account — Analytics/GradeTracker render their stat cards unconditionally (no EmptyState blocks), the empty-state hints carry the reference's verbatim copy, and the Settings Profile tab persists the study-profile fields (school/grade/1–12h goal/notifications master) on the User record via the preferences PATCH.
- **AI-accessibility contract (session-14):** AI output lands in `aria-live="polite"` + `aria-busy={busy}` regions (the assistant transcript pane, the solver's solution card) — async content never lands in a static container; errors announce via the aria-live toast stack.
- Layout with `flex gap-*` exclusively — margin utilities inside `space-y/x-*` containers are forbidden (v4 trap 4).
- Accent colors via `rgb(var(--sf-*))` inline styles or the generated `*-sf-primary-*` utilities; the v3-pinned palette and `--shadow-sm` pin must not be removed (traps 2 & 5, pinned by e2e specs).
- The radius scale is v3-identical from `md` up — do NOT re-pin it upward (trap 6); only `--radius-sm: 0.125rem` is pinned for v3 semantics. Opacity utilities serialize as oklab/lab in computed styles (trap 7) — e2e pins accept both serializations. `pt-*` after `p-*` REPLACES the shorthand's side (trap 8) — assert observable positions, not padding internals. The BLUR scale shifted one notch (trap 9): v3's `backdrop-blur-sm` (4px) is v4's `backdrop-blur-xs` — use `backdrop-blur-xs` where the reference measures 4px (drawer backdrop, login card). Colors serialize as their LEGACY forms (trap 10): modern `rgb(0 0 0 / 0.1)` syntax reads back as `rgba(...)`, and unpinned palette classes read back as `lab(...)` — pin every asserted color and write expectations in the serialized form.
- Primary CTAs use the Button `gradient` variant (`.sf-gradient` + `.sf-gradient-shadow` in globals.css) — sRGB-exact stops through the accent tokens; empty-state CTAs add `.sf-gradient-shadow-lg`. Never render solid-violet primary buttons.

**State (Zustand)**
- `useAppStore` (view/sidebar/drawer), `useThemeStore` (mode/accent/avatar), `useDataStore` + `mutations` (entity cache; every mutation refreshes the touched collections). No React Context for app state, no new state libraries. Theme vars go to `<html>` through `accentCssVars` — the COMPLETE 15-var token set (dropping tokens silently leaves stale violet values under other accents; the S4-G gradient/avatar/empty tokens and the S5 gradient hover stop are part of the set).

**Prisma / SQLite**
- Schema edits: update `prisma/schema.prisma`, then `bun run db:push`. Seeds stay idempotent (`bun run db:seed` is safe to re-run).
- The `db:*` scripts must keep setting `DATABASE_URL` inline (shell-provided env anchors correctly; `.env`-loaded env does not).

## Anti-Patterns to Avoid

- Real route folders per view (breaks the SPA contract + rewrites).
- `prisma db push` relying on repo-root `.env` (lands the db one directory high).
- `space-y-*` with margin-carrying children (Tailwind v4 trap 4).
- Removing the `@theme` pins (v3 palette / `--shadow-sm`) — parity e2e specs will fail.
- Importing `z-ai-web-dev-sdk` client-side.
- Re-implementing nav item markup instead of using `NavItemLink` (sidebar/drawer drift).
- Writing only SOME accent tokens to `<html>` (stale violet tokens under other accents).
- Hand-rolled page headers (use `ViewHeader`) or empty states (use the shared `EmptyState`/`SimpleEmptyState` reference pattern).
- Solid-violet primary CTAs (use the Button `gradient` variant — the reference's CTAs are violet→indigo gradients).
- Bare `[aria-pressed]` CSS rules (12 files use the attribute — scope to the Calendar containers).
- White-text-on-color surfaces without `sf-print-exact` (they print invisible when browsers drop backgrounds).
- `display: none` on the skip link (it must stay focusable — off-screen instead).
- Zinc/zinc-neutral form controls (the reference's shadcn theme is on the GRAY ramp — see globals.css).
- Routing brand/avatar gradients through `primary`/`strong` (they end at the ADJACENT hue — use `--sf-primary-gradient-to` / `-avatar-*`).
- Extra real logins in e2e specs (rate limiter poisons the run).
- Weakening lint/type gates to ship.

## Session Contracts (rebuild session — hard-won, verified)

- **`/api/auth/me` returns `{ ok, user }`** — the user row is NESTED. Reading the top level silently re-applies default theme/accent on every reload (loadFromUser falls back through `isAccent(undefined)` → violet). Unwrap: `const { user } = await apiGet<{ user: AppUser }>("/api/auth/me")`.
- **`mutations` is a standalone export** (`export const mutations = {…}` in `src/lib/data.ts`) — NOT a property of `useDataStore`'s state. `useDataStore((s) => s.mutations.createTask)` type-errors; import it directly.
- **`react-hooks/set-state-in-effect` is a lint gate.** The compliant patterns this repo uses: (a) render-derived selection (`effectiveId = selected && list.some(…) ? selected : list[0]?.id`), (b) key-remounted dialog forms with prop-initialized `useState` (`<TaskDialog key={dialogOpen ? \`open-${editing?.id ?? "new"}\` : "closed"} …>`), (c) deferred macrotask reactions (`window.setTimeout(complete, 0)` from the effect), (d) initial fetches INLINED in the effect (setStates after the await are fine; a wrapped async loader that sets state pre-await is flagged), (e) spinners flipped in event handlers, never in the effect body.
- **Never run `bun run build` while the e2e suite is running** — the standalone server keeps serving DELETED inodes (the S9 trap, re-verified twice). The webServer gate will pass while later specs chase ghosts.
- **The ESLint disable directives are NOT pre-seeded** — an unused `eslint-disable-next-line` is itself a lint error (`--report-unused-disable-directives`). Add them only where a rule actually fires.
- **`public/` must exist** — the build script copies it into `.next/standalone/`; a missing dir fails an otherwise green build.
