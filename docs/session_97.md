## The S114 lessons (AGENTS.md ×3)

1. **The overlay-interception trap** — a physical-coordinate click that
   "does nothing" is not evidence the control is broken: the reference's
   EMPTY fixed toast container (z-[100], w-full at 390, pointer-events auto,
   zero children) intercepted the physical click at the drawer X's (228,26)
   coordinates this pass; the elementFromPoint probe named the interceptor
   and the X button's own close function verified by the direct element
   click. The prior sessions' physical clicks all worked — the container
   renders state-dependently (a toast window), a TRANSIENT overlay, not a
   permanent defect. Probe the point BEFORE concluding.
2. **The skeleton-race content-wait trap** — a shell-state waitForFunction
   (`.dark` absent + `--sf-primary` set) passes on the BOOT-SCRIPT state
   BEFORE the view's client-fetched content renders: the pinning probe's
   first Notes dump returned an EMPTY main on a satisfied shell gate. Every
   capture gate must assert the SURFACE it protects, never the theme chrome
   alone — the theme gate and the content gate are separate predicates.
3. **The synthetic-vs-real click discipline** — an `el.click()` fired through
   eval does NOT trigger every React control: the sidebar collapse toggle
   silently ignored it (two probe rounds burned) while the drawer nav links,
   the drawer X and the theme options all took it. A control whose STATE
   must change gets the REAL click path (`find role button click --name`);
   the synthetic click is reserved for existence probes.
